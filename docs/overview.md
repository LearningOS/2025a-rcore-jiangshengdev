# ch8 补丁概览

本补丁围绕实验八引入的死锁检测需求，对内核的同步子系统和系统调用层进行了系统性调整，同时补全了 `sys_get_time` 的实现，便于用户态代码获取精确时间。

## 核心目标

- 在进程粒度上维护互斥锁与信号量的资源分配状态，并通过银行家算法判定是否存在潜在死锁。
- 在相关系统调用中按需开启或关闭死锁检测，一旦检测到风险便立即拒绝资源请求并返回 `-0xDEAD`。
- 确保互斥锁与信号量的生命周期事件（创建、加锁/解锁、P/V）都会同步更新资源状态。
- 补充 `sys_get_time`，提供以微秒计的系统时间，满足实验要求中对时间系统调用的依赖。

## 关键改动

- 新增 `DeadlockDetector` 组件，实现资源跟踪与安全性检查，并接入到进程控制块 `ProcessControlBlockInner`。
- 扩展同步系统调用流程：在 `mutex_lock`、`semaphore_down` 等路径上先“预演”资源请求，只有在保持安全状态时才真正阻塞等待并提交分配。
- 在资源释放（`mutex_unlock`、`semaphore_up`）与创建时及时刷新检测器状态，确保可用量与请求表一致。
- 实现 `sys_enable_deadlock_detect`，让用户进程按需控制死锁检测。
- `sys_get_time` 读取内核时间（秒、微秒）并写回用户提供的 `TimeVal` 结构。

## 影响范围

- 同步模块与系统调用层均有改动，任何与互斥锁、信号量交互的用户程序都可能观察到新的错误码与行为。
- 进程控制块结构新增字段，涉及进程创建、fork 等代码路径。
- 时间系统调用现已可用，相关测试与用户程序可直接调用。

## 建议测试

- 在开启/关闭死锁检测两种模式下，运行实验提供的互斥锁与信号量测例，确认安全路径不受影响。
- 构造互斥锁或信号量的循环保留请求，验证是否快速返回 `-0xDEAD` 并无实际阻塞。
- 调用 `sys_get_time` 并核对返回值的单调递增与单位换算是否正确。
